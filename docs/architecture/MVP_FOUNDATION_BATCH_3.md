# WayHunter common foundation handoff

## Ownership and routes

- **Person 1** owns Auth, Home, Advertisements, Traveller, Trip Planning, Active Trip, Safety, Memories, Friends, Profile, Settings and Notifications.
- **Person 2** owns Hunter, Places, Games, Coins, Wallet, Redemption, Vouchers and Shared Leaderboard.
- Register screens in your own `lib/app/router/person1_routes.dart` or `person2_routes.dart`. Screen builders and feature-private routes live in your feature. Use `AppDestination` and typed references for cross-owner navigation. Review changes to existing shared names and argument types together. The [Batch 1 notes](MVP_FOUNDATION_BATCH_1.md) show the registration pattern.
- The app composition imports both registrars. Features depend on shared route/reference contracts and shared services, plus their own code. Cross-feature reads should use a small injected interface owned by the producer, with no imports of another feature's views, HTTP adapters or DTOs.
- Use `WayhunterPageScaffold` for a top-level gradient surface and the [Batch 2 widgets](MVP_FOUNDATION_BATCH_2.md) for forms, buttons, cards, confirmation, and states. Provide caller copy and a presentation tone. Translate shared and feature copy with the same locale when locale selection is added.

## API and session

Run with `--dart-define=WAYHUNTER_ENV=staging --dart-define=WAYHUNTER_API_BASE_URL=<https-origin>` when an approved environment is supplied. A base path is optional. Omit the URL for offline starter development. The client treats absent, malformed and non-HTTPS URLs as unavailable. The environment label and URL are public build configuration. Supply tokens only through the session.

Under the production bootstrap, read `FoundationServices.of(context)` at the composition boundary and inject the service your feature needs. Outside widgets, use constructor injection. Use `ApiClient.request` with a method, verified path segments, query fields and an optional JSON body. Set `requiresSession: true` on confirmed protected calls. Register concrete paths and decode DTOs only in feature-owned adapters. Catch `ApiException` and map its category to a feature state. Error categories contain neither response bodies nor credentials. Redirects are disabled. A timeout bounds the caller's wait and does not establish that the server aborted the operation. Reconcile uncertain mutations before offering a retry.

The session starts signed out. When M1 wires the Auth flow, call `restore()` at that boundary to load a saved credential and verify eligible access with the backend. A restored local credential does not establish server authorization. Observe `SessionController` with a `ListenableBuilder`. Call `authenticate()` with a confirmed server-issued user reference and token. On explicit logout, let the owning feature invoke any confirmed revocation contract as applicable, then await `clear()`. Call `expire()` when the feature has confirmed the current session is expired. A 401 alone does not mutate the session, and there is no implicit refresh. Clear and expiry immediately remove token access. Handle credential deletion failures and retry the clear before treating durable logout as successful. Credential replacement first clears the old secure slot, then saves the new credential before exposing it. A failed pre-clear aborts the write. A failed write triggers a cleanup attempt, and both errors are surfaced if cleanup also fails. If physical storage refuses a delete or the app stops before the delete completes, the controller cannot guarantee that the persisted slot was erased. Token access stays disabled in that controller. Surface the storage failure and retry the clear before treating logout or replacement as durable. Revalidate restored sessions against the backend before trusting access. Concurrent restore callers await the same read. Registration and OTP development remains on the existing task branches.

Android uses Keystore-backed secure storage and separates credential slots by environment and API base URL. The plugin requires Dart 3.8 or newer and Android API 24 or newer. The current lockfile resolves dependencies requiring Dart 3.13 or newer. Android app backup is disabled. Unsupported platforms and missing configuration bind `UnavailableCredentialStore`. Tests inject deterministic in-memory credentials and a fake transport. Keep those bindings out of production bootstrap, and use synthetic values only.

## Device adapters and integration gates

The default services return unavailable for permission checks/requests, map availability and upload status. Location and live photo/video return typed unavailable failures. Add future concrete adapters behind the interfaces in `core/services/device_interfaces.dart` and bind them through `FoundationServices` after device and platform requirements are agreed. Keep privacy consent and evidence policy in the owning feature.

Use the [Mobile/Admin integration handoff](../integration/WAYHUNTER_MOBILE_ADMIN_INTEGRATION.md) and the approved backend snapshot to confirm feature routes, response and error DTOs, auth, and retry semantics. Priority gaps include Hunter/Games and their rankings, published-place reads, Wallet history collections, session and profile policy, and authorized notification targets. Verify backend behavior in the agreed environment before enabling real adapters.
