### Transport and session findings

- Supply an explicit `WAYHUNTER_API_BASE_URL=https://<trusted-host>:<port>` with no `/api` suffix. The client builds full API paths. Missing or invalid configuration fails closed. The normal transport disables redirects, attaches bearer tokens only for protected requests, uses platform TLS validation and has a 15-second timeout. Development CORS uses explicit configured origins in backend source. Web needs an exact allowed origin and a supported credential-store design before claiming authenticated parity.
- Use approved HTTPS staging or a developer HTTPS reverse proxy to the local ASP.NET Core listener. Bind the proxy where the emulator can reach it, use a hostname or IP in the certificate SAN and a chain trusted by that Android build, and keep the upstream listener on the development host. If using `https://10.0.2.2:<port>`, the certificate must cover that IP. This batch retains HTTPS-only configuration. If an HTTP exception is needed later, require an explicit opt-in for Android debug, `development` and exact host `10.0.2.2`, plus a debug-only Android network security rule. Profile, release, web, staging and production must retain HTTPS.
- Android production bootstrap namespaces encrypted credentials by environment and API URI. Session operations serialize durable writes and clearing, remove the token from memory during account replacement or clear, and guard superseded storage operations. Restored sessions require an owner-matching `/me` response. Fresh sign-in accepts the server-issued token after checking its expiry. Protected navigation is disposed on sign-out. Owner-bound adapters and session-keyed Game/Wallet widgets guard private UI state. Existing mocked coverage includes delayed content, account changes and storage failures. Live process restart, revocation and account-switch behavior remain unverified.
- HTTP 401/403/404/409 map to unauthorized/forbidden/not found/conflict. Network and timeout are distinct, 5xx maps to server failure, other non-success statuses map to rejection, and malformed success JSON maps to invalid response. Startup clears on 401/403 and rejects a mismatched owner. Feature-screen 401s do not consistently transition the whole app to sign-in. A 403 may represent resource-specific denial. Backend OTP cooldown uses 429 and `Retry-After`; Flutter uses a fixed local cooldown and the shared client does not surface that header. Neither condition authorizes automatic replay of ambiguous writes.

### Backend boundaries

- `Identity:EnableSharedAuthentication` and JWT issuer/audience/signing configuration are required for trusted sessions. M2 SQL persistence, M3 SQL sessions/memories, M6 voucher/reward SQL and M7 advertisement SQL are deployment-dependent. Confirm actual runtime flags and storage against the authorized environment before a device run.
- M5 draft controller registration requires shared auth and either `Games:EnableSqlPersistence` or Development with `Games:EnableDevelopmentDraftHttpApi`. The Admin creation-review controller requires shared auth plus Games SQL. `Games:EnableExpiryWorker` controls background archive with SQL. Keep public reads and creator history separate. Archive retains My Games and audit history. Expired games cannot start, resume, finish or produce a winning approval. Preserve approved creation/winner rewards at +100 each and Welcome at +100 for eligible activation. Mobile displays server state and awards.
- Backend notification tests cited in the handoff exercise tested workflow components. The pinned app startup still binds unavailable inbox, jobs, device and push interfaces. Outbox worker configuration does not supply those bindings. Confirm a runtime backend fix and deployed probe before marking notifications demo-ready.
- M4 owner IDs come from trusted authentication. Use approved live location plus the camera flow and backend-issued private-media verification. Keep guided 360° and normal live photo requirements, no gallery evidence, and never model a camera file or client GPS value as a trusted receipt. M5 player proof remains live camera only. Creator hint imagery has a separate policy.
- Resend email, Google Maps/Places/Routes, Gemini, Cloudinary and external notification delivery need provider configuration and live confirmation. Trip Memory media, M4/M5 capture receipt issuance and verification, and voucher image bytes need approved private-media contracts. No database, provider or monetary operation ran in this audit.
